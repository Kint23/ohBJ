## 一、作品简介

### 填表版（194 字 · 单段 · 直接粘贴）

> 表单要求：**描述你的应用解决什么问题、核心功能、用到了哪些百度地图 API/SDK（200 字以内）**。
> 下面这段按「问题 → 核心功能 → 百度 API」三段式写，实测 **194 字**（含标点与空格），留 6 字余量。

《帝京景物略》记下127处北京地名，如今在导航里几乎消失。「帝京寻踪」把21万字古籍拆成语料，为30处可考者落回现代坐标，点开即见原文、旧诗、白话今译与清人核访，湮灭者只画范围圈。卷次/类型/步行圈三重筛选，一句「半天想逛寺庙」即出三种方案与真实里程。百度地图API：JSAPI GL（标记、范围圈、路线线、周边检索、地理编码）、步行/骑行/驾车/公交路线规划、WebAPI地点检索核验。

**用到的百度地图能力（评委问起时对照）**

| 能力 | 调用处 | 用途 |
|---|---|---|
| JSAPI GL 地图底座 | `new BMapGL.Map` / `Point` / `ScaleControl` | 底图、中心与缩放、比例尺 |
| 覆盖物 | `BMapGL.Marker` / `Label` / `Circle` / `Polyline` / `InfoWindow` | 30 处标记与标注、已湮灭地名的范围圈、行程连线与编号、详情气泡 |
| 周边检索 | `BMapGL.LocalSearch.searchNearby(kw, pt, 1000)` | 一键找附近餐饮 / 厕所（1 km 内） |
| 地理编码 | `BMapGL.Geocoder` | 核验面板：地址 → 坐标，偏差 < 3 km 自动写回并标记「已核验」 |
| 路线规划 | `BMapGL.WalkingRoute` / `RidingRoute` / `DrivingRoute` / `TransitRoute` | 步行 / 骑行 / 驾车 / 公交 / 混合，取真实里程与耗时 |
| WebAPI 地点检索 | `place/v2/search` | 离线流水线回核 30 处坐标（30/30 命中） |
| WebAPI 地理编码 | `geocoding/v3/` | 离线把今名地址解析成经纬度 |

> 坐标换算链 **WGS-84 → GCJ-02 → BD-09** 由本地脚本完成，不消耗线上配额。

### 散文版（约 150 字，宣传 / 表单放宽时用）

> 四百年前的北京写在纸上，今天的北京长在地图上。
> 《帝京景物略》以八卷录下 127 处风物、1346 首诗，而"太學石鼓""弘仁橋"这些名字，在导航里早已杳然。
> **帝京寻踪**以一条可复现的流水线把古籍拆成结构化语料：抽取 127 目、分离诗文，为 30 处有明确古今传承的地名建立映射，坐标经 WGS-84→GCJ-02→BD-09 换算，并以百度地点检索逐一回核，30 处悉数命中；已湮灭者画作范围，不下妄断。
> 于是点一个明清地名，便可读到原文、旧诗、白话今译与清人核访；说一句"半天想逛寺庙"，智能排线即给出三种取舍，一键成行。

### 长版（约 500 字，作品详情用）

> **一句话**：把四百年前的北京，叠回今天的地图。
>
> **问题**：明代刘侗《帝京景物略》按"城北内外—城南内外—西山上"八卷记下 127 个地点、上千首诗，
> 是理解北京城最生动的一手材料。但这些地名在今天的导航软件里几乎全部消失：
> "太學石鼓"是国子监，"憫忠寺"是法源寺，"崇國寺"是护国寺，"弘仁橋"是马驹桥。
> 普通读者只有两个选择——要么读不懂，要么走不到。
>
> **做法**：
> 1. **抽取**——用可复现的解析器把 21 万字古籍切成 127 目，自动分离正文、诗词、作者与朝代，
>    并识别"附目于主目"的嵌套结构（如净业寺附水关）。
> 2. **落点**——建立"明清地名 → 今地名"的策展映射，坐标经 WGS-84→GCJ-02→BD-09 换算，
>    再用百度地图 WebAPI 回核；已湮灭的地名以范围圆呈现，不伪装成精确点。
> 3. **呈现**——百度地图 JSAPI GL 单页：卷次/类型/步行圈三重筛选，点击标记即见
>    原文摘录（支持繁简切换）、关联诗词、白话今译，以及清人《京城古迹考》对同一地点的"臣按…今查…"
>    （**清代文言原文与白话今译并列**，与明代原文同等对待）。
> 4. **出发**——内置 8 个半日步行圈与 2/3/5 日三档行程；
>    更可以只说一句「半天想逛寺庙」，智能排线就会用三种不同策略各排一条线，
>    给出 3 个取舍不同的方案（紧凑少走 / 主题深游 / 内容丰富），
>    每套标出总里程、交通耗时、参观耗时与匹配度；
>    选定后一键调用百度路线规划（步行/骑行/驾车/公交/混合）算出真实里程与耗时，
>    并可跳转百度地图导航、检索周边餐饮与厕所。
>
> **技术深度**：数据流水线全脚本化（抽取 → 构建 → 核验 → 自检），
> `validate.py` 可复现全部里程数字（路线标注与直线距离之和误差 < 1%），
> 每个地点带坐标置信度与来源标记，数据可追溯、可复现。
>
> **实用价值**：既是给游客的城市漫步工具，也是给研究者的可检索古籍索引。

### 怎么让视频直接显示在 GitHub 介绍页里？（已实测）

GitHub 的 README 渲染会**过滤 `<video>` / `<iframe>`**（实测：`<video>` 标签被整个删掉，只留空段落），
所以只有两条路：

1. **可点击动图**（当前方案，最稳）：
   `[![点此播放 60 秒正片](banner/teaser.webp)](https://kint23.github.io/ohBJ/video/demo.mp4)`
   动图在 README 里自己循环播放（GitHub 允许 `<img>`），点一下就打开正片播放器。
2. **GitHub 附件 URL**（真·内嵌播放器）：把 MP4 拖进 Issue/评论输入框上传，
   得到 `https://github.com/user-attachments/assets/<uuid>` 形式的链接，**单独成行**放进 README，
   GitHub 会渲染成内嵌播放器。
   ⚠️ 附件大小上限约 25 MB/文件（免费账号），本片 53 MB 需先转码 720p（约 15–20 MB）再传。

> 重新生成 README 预览动图：
> ```powershell
